Open-source governed-agent toolkit

A governed agent is a stack, not one package.

Qarinah preserves project context. Maqam gates registered effects. Cockroach Browser provides authorized interactive sessions. Cockroach Crawler acquires bounded web evidence. Established runtimes and primitives keep their own identities around that project family.

The short answer

Compose explicit responsibilities instead of stretching one tool across the system.

The four authored projects are separate open-source products. They can be installed independently and keep different runtime, authority, and license boundaries. Calling them a toolkit describes a useful composition, not one bundled platform.

LangGraph or OpenAI Agents SDK can own the agent. Playwright or Puppeteer can own low-level browser control. Browser Use or Stagehand can own higher-level browser-agent interaction. Trafilatura, Firecrawl, or Docling can own extraction and ingestion jobs that fit their documented center.

01

Authored project family

Four projects, four explicit boundaries.

Adopt the missing boundary. The projects do not require one another for their primary local workflows.

01.1

Qarinah

Official site ↗
Product center

Local, evidence-linked project memory and bounded cited context packs for supported coding agents.

Boundary

Qarinah does not run the agent loop, execute browser actions, or grant tool authority.

Source: github.com/AjnasNB/qarinah

01.2

Maqam

Official site ↗
Product center

Policy before registered TypeScript actions, exact-input approval, default one-use consumption, and execution receipts.

Boundary

Calls that bypass a registered Maqam gateway stay outside its control. Maqam is not complete enterprise governance or universal interception.

Source: github.com/AjnasNB/maqam

01.3

Cockroach Browser

Official site ↗
Product center

Explicit browser sessions, semantic interaction, bounded evidence, audits, and human handoff for browser-capable agents.

Boundary

Cockroach Browser uses Playwright and Chromium. It adds session authority and evidence contracts; it is not a new browser engine and does not bypass access controls.

Source: github.com/AjnasNB/cockroach-browser

01.4

Cockroach Crawler

Official site ↗
Product center

Web collection, rendering, extraction, and normalized evidence under creator-owned origin, request, byte, redirect, concurrency, and time limits.

Boundary

It is not a hosted proxy fleet or an access-control bypass. Its optional quality surface uses Trafilatura as a disclosed dependency.

Source: github.com/AjnasNB/cockroach-crawler

02

Browser primitives and agent frameworks

Choose the browser layer by the contract you need.

Low-level automation, AI-assisted interaction, and authorized agent sessions are related jobs with different centers.

02.1

Playwright

Official documentation ↗
Official center

Browser automation and testing for Chromium, Firefox, and WebKit through one API.

Composition

Cockroach Browser uses Playwright for browser control and adds its own session-authority, evidence, audit, and handoff boundary.

02.2

Puppeteer

Official documentation ↗
Official center

A high-level JavaScript API for controlling Chrome or Firefox over DevTools Protocol or WebDriver BiDi.

Composition

Use it directly when host code should own browser authority, session policy, evidence, and approval behavior.

02.3

Browser Use

Official repository ↗
Official center

An open-source framework that makes websites available to AI agents, with optional cloud services.

Composition

Evaluate its agent autonomy and deployment model separately from Cockroach Browser's explicit session boundary.

02.4

Stagehand

Official documentation ↗
Official center

A browser automation framework combining code and natural-language act, extract, observe, and agent interfaces.

Composition

Use it when AI-assisted interaction authoring is central, then add a separate governance boundary where the host requires one.

03

Web and document acquisition

Traversal, extraction, web-data APIs, and document conversion are separate decisions.

Choose the smallest product center that covers the source types and deployment model in the workload.

03.1

Trafilatura

Official documentation ↗
Official center

A Python package and CLI for web discovery, downloading, and extraction of main text, metadata, comments, and links.

Composition

Cockroach Crawler discloses Trafilatura as its optional quality dependency rather than presenting that extraction algorithm as its own.

03.2

Firecrawl

Official documentation ↗
Official center

A managed or self-hosted web-data platform with search, scrape, crawl, map, browser, and agent surfaces.

Composition

Start here when a broader web-data platform fits better than Cockroach Crawler's local TypeScript acquisition and evidence boundary.

03.3

Docling

Official documentation ↗
Official center

Document conversion across PDF, office documents, HTML, images, and other formats into a unified document representation.

Composition

Use it when file conversion, document structure, export, chunking, and AI ingestion matter more than site traversal or browser interaction.

04

Agent and workflow runtimes

Let the runtime own the agent loop.

The authored project family supplies optional adjacent boundaries. It does not need to replace orchestration, models, tools, handoffs, or durable workflow state.

04.1

LangGraph

Official documentation ↗
Official center

Low-level orchestration for long-running, stateful agents with durable execution, streaming, memory, and human-in-the-loop control.

Composition

LangGraph can own the workflow while Qarinah supplies project memory and Maqam governs selected registered effects.

04.2

OpenAI Agents SDK

Official documentation ↗
Official center

A TypeScript agent runtime with an agent loop, tools, handoffs, sessions, tracing, guardrails, and human-in-the-loop mechanisms.

Composition

The SDK can build and run the agent while the authored projects provide optional memory, browser, acquisition, and registered-action boundaries.

Direct answers

Questions about authorship and composition.

Is this one bundled agent platform?

No. Qarinah, Maqam, Cockroach Browser, and Cockroach Crawler are separate open-source projects that can be adopted independently. The other named tools are third-party primitives or integration choices.

Does Cockroach Browser replace Playwright?

No. Cockroach Browser uses Playwright and Chromium. Its separate contribution is an explicit session-authority, evidence, audit, and human-handoff boundary for agent use.

Does Maqam govern every action an agent can take?

No. Maqam governs registered actions deliberately routed through its gateway. Calls that bypass that boundary remain outside its control.

Are the established tools products by Ajnas N B?

No. Playwright, Puppeteer, Trafilatura, Firecrawl, Browser Use, Stagehand, LangGraph, OpenAI Agents SDK, and Docling are third-party projects linked to their official documentation.

Does this page identify a universal winner?

No. It compares documented product jobs and composition boundaries. It contains no matched cross-product benchmark and makes no universal quality claim.
